## 1. Project Identity
- **Name:** Meridian Bank (folder `Bank`, package name `bank`) — **Type:** full-stack web app (Next.js monolith: UI + Server Actions + Prisma).
- **Purpose:** a *demonstration* retail-banking platform: sign-up with e-mail OTP, accounts, transfers with OTP step-up, payees, debit cards, loans, investments, notifications, KYC, TOTP 2FA, and a staff/admin console. **No real money or payment rails**; everything external is simulated.
- **Stack (confirmed from package.json / schema):** Next.js 15.5.29 (upgraded from 15.5.21 on 2026-11-16; App Router, Server Actions), React 19, TypeScript 5, Prisma 6.19.3 on **PostgreSQL** (17.4 locally), Zod 3, react-hook-form, Tailwind CSS v4 + shadcn/ui (Radix), Framer Motion, Recharts, `argon2` (native), `jose` (JWT), `otpauth` + `qrcode` (TOTP), Vitest 4. Node ≥ 20 (tested 22.17.1).
- **Status:** feature-rich demo; builds, runs, and **all core banking operations are verified by automated tests against a real database** (§6a). The critical/high security and money-integrity defects found in the audit are **fixed**; OTP e-mail delivery, silent session refresh and trusted-proxy IP handling are now implemented and live-tested. Remaining gaps (a verified e-mail domain, PII encryption, major-version dependency upgrades, multi-instance rate limiting, UI/browser tests — §5/§6) mean it is **still not fully production-ready**. Partial areas: support tickets (placeholder), marketing sub-pages (placeholders).

## 2. Functional Context
**Implemented (verified by reading the source; flows were not exercised in a browser):**
- **Auth:** signup (Zod; password ≥ 12 chars + upper/lower/digit/symbol + small common-password list) → e-mail OTP verify → ACTIVE + two starter accounts (`CURRENT`, `SAVINGS`) → session. Login with failed-attempt lockout (5 → 15 min), optional TOTP 2FA step, forgot/reset password (30-min single-use token, revokes sessions), change password.
- **Accounts/transactions:** list, detail, filterable transaction history, CSV export (`/api/transactions/export`), monthly activity chart.
- **Transfers:** internal (own accounts) and to *verified payees* (money just leaves the system). Flow: initiate → OTP challenge (`bank_pending_transfer` cookie holds the transfer) → confirm → atomic debit. Limits: $5,000 per transfer, per-account daily limit (default $10,000), duplicate-transfer warning within 2 min.
- **Deposits:** simulated, ≤ $50,000 each, 10/hour. **Payees:** add + "verify" (instant mock). **Cards:** issue (virtual/physical), freeze/unfreeze, replace, controls, OTP-confirmed PIN change; number & CVV AES-256-GCM encrypted. **Loans:** instant auto-approval within product bounds, EMI schedule, manual EMI payments. **Investments:** FD/RD/mutual fund/stock with deterministic pseudo-returns; early-withdrawal penalty. **KYC:** PAN/Aadhaar + 4 images (base64 in Postgres), admin review. **Notifications:** in-app only. **Security settings:** TOTP 2FA setup/disable, session list + revoke, login history.
- **Admin (`/admin`, staff roles):** dashboard, user list/detail, status changes, role changes (SUPER_ADMIN only), KYC review, audit-log viewer.
- **Placeholders (not implemented):** support ticketing (`SupportTicket` model exists, no actions/UI), marketing sub-pages (`ComingSoon`), real OTP/e-mail/SMS delivery, real payment/KYC providers.

**Business rules to preserve:** every customer query is scoped by the authenticated `userId`; money moves only inside DB transactions; debits use a conditional `updateMany` (`balance >= amount`); staff permissions are tiered (`src/lib/auth/admin.ts`); OTP: 6 digits, 5-min TTL, 5 attempts; roles: `CUSTOMER, SUPPORT_AGENT, AUDITOR, ADMIN, SUPER_ADMIN`.

## 3. Technical Context
**Architecture:** one Next.js app. Route groups under `src/app`: `(marketing)`, `(auth)`, `(app)` (customer dashboard under `/dashboard`), `(admin)`. Mutations are **Server Actions** in `src/actions/**` (`"use server"`); reads are Server Components calling `src/lib/**`. Only two Route Handlers exist: `GET /api/auth/session-expired` (clears cookies → `/login`) and `GET /api/transactions/export`.

**Important files**
| File | Why it matters |
|---|---|
| `src/middleware.ts` | Per-request CSP nonce + security headers; redirects unauthenticated users from `/dashboard`, `/admin`; redirects authenticated users away from auth pages. Only verifies the JWT signature (no DB). |
| `src/lib/auth/tokens.ts` | JWT (HS256, `AUTH_SECRET`) for access tokens **and** purpose tokens; opaque refresh tokens (SHA-256 stored); OTP/opaque-token generators. |
| `src/lib/auth/session.ts` | `createSession`, `getCurrentUser` (JWT + active user, **not** session revocation), `rotateSession` (**never called**), session helpers. |
| `src/lib/auth/cookies.ts` | `bank_access_token` (TTL 900 s) / `bank_refresh_token`; httpOnly, SameSite=Strict, Secure in production. |
| `src/lib/auth/otp.ts` | OTP issue/verify; logs the code in non-production (the only "delivery"). |
| `src/lib/auth/pending-{2fa,verification,transfer}.ts` | Signed purpose-token cookies for multi-step flows. |
| `src/lib/security/{encryption,rate-limit,audit,request-context}.ts` | AES-256-GCM helpers; in-memory fixed-window rate limiter (`RATE_LIMITS`); audit/login-history writers; client-IP extraction. |
| `src/actions/banking/transfer.ts` | Most important money flow (initiate → OTP → atomic confirm). |
| `src/lib/banking/{limits,loans,investments,identifiers,queries}.ts` | Limits, EMI math, investment valuation, ID/card generators, user-scoped queries. |
| `src/lib/validations/*.ts` | One Zod schema file per domain. |
| `prisma/schema.prisma` (+3 migrations) | 20 models; amounts are `Decimal(18,2)`. |
| `src/lib/auth/admin.ts`, `src/lib/admin/queries.ts` | Role predicates, `requireStaffUser`, cross-user admin queries. |

**Folders:** `src/actions` (auth, banking, admin, kyc, profile, security, two-factor, notifications) · `src/components` (`ui` shadcn, `app`, `admin`, `marketing`) · `src/lib` (auth, banking, security, validations, admin, db) · `src/test` (Vitest setup/stub) · `prisma`.

**Database (PostgreSQL via Prisma; table names are `@@map`ped lower-case plural, e.g. `users`):** `User` (role, status, email/phone unique, argon2 `passwordHash`, `twoFactorEnabled/Secret(encrypted)`, lockout fields) → `Session` (hashed refresh token, `revokedAt`, device), `Device`, `LoginHistory`, `OtpCode` (hashed), `PasswordResetToken`, `VerificationToken` (unused by actions), `Account` (12-digit number, `balance`, `dailyTransferLimit`), `Transaction` (reference number, type/status, sender/receiver account or beneficiary, `amount`, `balanceAfter`), `Beneficiary`, `Card` (encrypted PAN/CVV, `pinHash`), `Loan`, `Investment`, `Kyc` (+`KycDocument` data-URL files), `Notification`, `SupportTicket` (unused), `AuditLog`. Enums for roles, statuses, types, purposes.

**Authentication flow:** login → (verification pending? → OTP) → (2FA? `bank_pending_2fa` cookie → TOTP) → `createSession`: DB `Session` row + access JWT (`sub, role, sessionId`, 15 min) + refresh token cookie. Every page/action calls `getCurrentUser()`, which verifies the access JWT and loads the user (must be `ACTIVE`). `/admin/**` additionally calls `requireStaffUser()`; admin actions re-check `canManageUsers/canManageRoles`.

**Server-Action "API":** there is no REST API; actions return `{ success, error? }` unions. CSRF: Next.js Server Actions Origin check + SameSite=Strict cookies.

**Dev-only behaviours:** OTP codes and reset tokens are `console.log`ged when `NODE_ENV !== "production"`; there is no real delivery.

## 4. Implementation notes
- Transfer confirm (`confirmTransferAction`) trusts the signed pending-transfer cookie and re-verifies nothing except the debit's conditional `updateMany`.
- Investment value = `principal × (1 + rate × years)` plus (for stocks/funds) a deterministic ±6 % "wiggle" seeded by `investmentId + date` (`lib/banking/investments.ts`).
- EMI via standard amortisation formula; the repayment schedule is computed on the fly.
- Rate limiting keys are `action:ip:email` or `action:userId`, in process memory (resets on restart; single instance only).
- CSP: strict nonce + `strict-dynamic`; the root layout's `headers()` read is what makes Next stamp the nonce on its scripts — **do not remove it**. The whole app is therefore dynamically rendered.

## 6. Known Issues, Technical Debt, Limitations
- **E-mail delivery needs a verified domain for real customers.** Codes/links are e-mailed through Resend and work (live-tested), but until a domain is verified at resend.com/domains the sandbox sender `onboarding@resend.dev` can only deliver to the Resend account owner's own address. There is **no SMS** channel (phone numbers are collected but never verified or used).
- ~~No session refresh~~ → **implemented** (§6d): the old unused, rotating `rotateSession()` was replaced by a non-rotating `refreshSession()`; sessions now last their full lifetime (30 days with "remember me", ~7 otherwise). Trade-off: refresh tokens are not rotated (rotation races under parallel requests), so a stolen refresh cookie works until the session is revoked/expires — mitigated by hashing, server-side revocation checked on every request, httpOnly + SameSite=Strict cookies, and revocation on password change/reset/logout.
- **KYC uploads:** four base64 images are sent in one Server Action (≈ 2.5 MB allowed each). `next.config.ts` sets `experimental.serverActions.bodySizeLimit: "15mb"` (the default 1 MB made real photos fail). **Verified live (§6c):** a 4.6 MB four-photo submission is accepted, per-file validation still rejects oversized images, and a 16 MB request is refused. Still never exercised through the real UI in a browser.
- Dev database `bank_dev` has **0 users but 62 transactions and 272 audit-log rows** (leftovers); no admin exists and there is no seed script (promote a user with SQL; see How to run.md).
- Placeholders: support tickets, marketing sub-pages. `VerificationToken` model unused.
- Tests: **106 passing** — 61 unit tests (encryption, rate limiter, admin permissions, KYC validation, formatting, safe-redirect, e-mail client + templates, middleware refresh, client-IP parsing) + 45 integration tests (§6a). **No component/UI/browser tests** (Playwright would be a new dev dependency; not added).
- No git history in this folder (no commits yet) — commit before further changes. The CI workflow `.github/workflows/ci.yml` (Postgres service, `tsc`, lint, tests, build, `npm audit --audit-level=critical`) has never run on GitHub.
- Rate limiting is still **in-process memory** (fine for one instance; use a shared store such as Redis before running several instances).
- A clock caveat: the dev PC's clock appeared ~2½ minutes ahead of Resend's during testing; compare e-mail IDs, not timestamps, in scripts.
- ~~Build prints "Compiled with warnings"~~ → **fixed 2026-11-16**: it only appeared on *clean* builds (incremental builds hid it). Cause: `src/middleware.ts` imported the whole `jose` package, whose JWE/compression code isn't supported by the Edge runtime. Fix: `import { jwtVerify } from "jose/jwt/verify"` (the middleware only verifies signed JWTs). Verified with a clean rebuild (0 warnings) and a live re-run (35/35). **Tip:** when checking build output, delete `.next` first.
- Outdated: several minor updates available (`npm outdated`), Prisma 7 / ESLint 10 / Framer Motion 14 are majors.
- **Existing sessions were invalidated by the 2026-11-16 token change** (access tokens now carry `typ:"access"`): everyone signs in again once.
- ~~Pending-transfer cookie replay~~ → **closed 2026-11-16**: pending transfers/PIN changes are single-use server-side records (§6d) and each one-time code is bound to its own record.

## 6d. Architecture added on 2026-11-16 (second round)
- **E-mail** (`src/lib/email/send.ts`, `templates.ts`): plain-`fetch` Resend client — 10 s timeout, one retry on network/5xx/429, never throws, never logs keys/recipients/bodies, refuses to send under `NODE_ENV=test`. Env: `RESEND_API_KEY` (send-only key), `EMAIL_FROM`. Templates escape every dynamic value. `issueOtp` e-mails the code (transfer e-mails state the amount/note); dev also prints it; production never logs it. Forgot-password sends a link `${NEXT_PUBLIC_APP_URL}/reset-password?token=…` after the response (`lib/after-response.ts`, so timing doesn't reveal whether an account exists), only the newest link is valid, and it is rate-limited per address as well as per IP.
- **Sessions** (`lib/auth/session.ts`, `cookies.ts`, `app/api/auth/refresh/route.ts`, `middleware.ts`): access JWT 15 min (`typ:"access"`, `sessionId`), refresh token 30 d/≈7 d (hashed in DB). When only the refresh cookie remains, **the middleware calls `POST /api/auth/refresh`** (Node runtime) and forwards the new `Set-Cookie` both to the browser and to the request being served, so pages *and* Server Action POSTs continue seamlessly. Refresh does not rotate the token (race-free). Every request re-checks the session row (`getCurrentUser`), so revocation is immediate.
- **Pending actions** (`prisma/schema.prisma` model `PendingAction`, migration `20261116000000_add_pending_actions`, `lib/auth/pending-action.ts`, `pending-transfer.ts`): transfer and PIN-change details live in the DB; the cookie holds only a signed `pid`. Consumed exactly once **inside the money transaction**; starting a new one retires the old; `OtpCode.contextRef` binds each code to its pending action.
- **OTP** (`lib/auth/otp.ts`): HMAC-SHA-256(`AUTH_SECRET`, user+purpose+code), constant-time compare, `randomInt` digits, atomic one-time claim.
- **Client IP** (`lib/security/client-ip.ts`, `request-context.ts`): `X-Forwarded-For` is only used when `TRUSTED_PROXY_HOPS` ≥ 1 (Nth entry from the right); default 0 = no IP derived.
- **Tests/CI:** `src/test/middleware.test.ts`, `src/lib/email/email.test.ts`, `src/lib/security/client-ip.test.ts`, extra integration suites; `.github/workflows/ci.yml`.

## 7. Development Guidelines
- **New customer feature:** Zod schema in `lib/validations/<area>.ts` → server action in `src/actions/<area>/…` (`getCurrentUser()` first, `safeParse`, `checkRateLimit`, scope every query by `user.id`, write an `AuditLog`, `notifyUser` if relevant, `revalidatePath`) → UI under `src/app/(app)/dashboard/…` + client component in `src/components/app/`.
- **New admin feature:** call `requireStaffUser()` and the right `can…` predicate inside the action; keep cross-user queries in `lib/admin/queries.ts`.
- **Money:** always inside `prisma.$transaction`; debit with conditional `updateMany` and `increment`/`decrement` — never read-modify-write a balance.
- **Secrets/crypto:** use `encryptSecret/decryptSecret`; never log secrets; don't add new JWT types without a distinct `typ` and verifier.
- Migrations: edit `schema.prisma`, `npx prisma migrate dev --name …` on a **scratch** database, commit the migration, deploy with `migrate deploy`.
- Don't break: the `headers()` nonce read in the root layout, the per-user query scoping, `server-only` imports (tests alias them via `src/test/server-only-stub.ts`), `ENCRYPTION_KEY` stability.
